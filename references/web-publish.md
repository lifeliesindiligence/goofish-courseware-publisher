# 闲鱼网页发布与恢复

这些是一次已观察到的网页流程经验，不是稳定 API。每次依据当前界面重新识别控件和状态；页面变化时停下来检查，不能机械点击旧坐标或假定旧选择器仍有效。

## 发布前

1. 建立逐件记录：本地源文件及 SHA-256、旧商品链接（若有）、拟用标题、价格、文案、图片顺序、实际交付方式、发布状态。恢复任务时若源文件校验值已变，先重核图文与交付内容。不要把账户或商品 ID 写进公开 Skill 仓库。
2. 确认用户已登录，并且当前授权覆盖所需的创建、替换、下架动作。检查卖家列表，排除相同课件已经在售的重复商品。
3. 按“主封面、详情图”的顺序准备上传文件。检查源文件和图片路径存在、大小与格式符合页面限制。

## 填表和发布

1. 在发布页通过可观察的文件选择器上传。**等待每张图片出现实际上传完成的预览**；仅看到排序占位格不代表上传完毕。一次实践中，完整图片资源来自 `-2-fleamarket`，但这个特征只作辅助判断，须结合当前 UI 的上传状态。
2. 上传后重新检查类目。网站的智能归类可能把电子课件切到“其他服务”；仅在类目实际覆盖该商品、且当前页面允许真实履约时选择。填入用户指定价格和页面支持的交付设置。纯数字文件不应承诺实体邮寄；若页面只给实体物流、提示类目错误或要求无法真实完成的交付，保存草稿并停下核实。客服给出的类目名不能替代发品页与履约页的实测结果；出现矛盾时用具体报错追问，未解决前不要改挂近似类目发布。
3. 填标题和描述后读取表单显示值或预览。富文本描述的换行可能在提交时被合并；必要时用段落分隔，再在成品页核对。
4. 发布前一次性核对：图片顺序、标题、价格、类目、描述、交付方式，及卖家是否能按描述交付实际文件。点击发布一次并等待明确结果。不得用“实体商品附赠文件”、虚假物流或空包掩盖纯数字商品。

## 响应不明与替换旧商品

- 发布后未跳转或超时：先检查卖家列表是否出现目标标题，并打开可能的新商品核对。只有证据表明未创建时才重试，避免重复上架。
- 记录新商品 ID，打开完整链接，核对在售状态、价格、标题、描述、图片数量及主图。不要只凭表单回显判断。
- 旧商品页面若没有编辑入口，可用“新商品发布并核验 → 下架旧商品”的替换流程；下架后再确认旧商品状态。不要把“删除”作为默认替换手段。
- 新商品核验失败时，保留旧商品在售并记录失败原因。若已经误下架，先恢复用户可购买状态，再继续排查。
- 中途停止或会话丢失时，从逐件记录与卖家列表重建当前状态；每件商品根据证据恢复，不依赖上一轮工具调用是否返回成功。

## 交付

逐个打开将发给用户的完整 URL，确认最终页面确实可查看、可购买。给出已完成、未完成的准确数量和链接；不把内部草稿页、后台 URL 或过期旧链接作为商品入口。
